# 스킬 사본 (내구 저장용)

## 왜 여기 있나

글쓰기 스킬(`gym-blog-writer` 등)의 실제 파일은 **이 리포 밖**인
`~/.claude/skills/` 에 있다. 그런데 원격 세션의 컨테이너는 일정 시간 뒤 회수되므로,
세션에서 스킬을 고치면 **커밋하지 않는 한 그 편집이 사라진다.**

2026-08-06 세션에서 실제로 그럴 뻔했다. 실측으로 고친 내용(메인 키워드 5회 근거,
서브 키워드 하나로 축소, 신뢰 단락의 연차·경력 제거, 상호명 3회의 성격 정정)이 전부
`~/.claude/skills/gym-blog-writer/SKILL.md` 에만 있었고 리포에는 없었다.

그래서 **여기에 사본을 둔다.** 이 폴더는 「지금 쓰는 스킬이 이런 상태다」의 기록이다.

## 어느 쪽이 진짜인가

**`~/.claude/skills/` 쪽이 실제로 동작하는 파일이다.** 이 폴더는 사본이다.
스킬을 고쳤으면 두 곳을 같이 맞춰야 한다:

    cp -r ~/.claude/skills/gym-blog-writer docs/skills/     # 리포에 저장
    cp -r docs/skills/gym-blog-writer ~/.claude/skills/     # 리포에서 복원

`.claude/skills/` 에 두지 않은 이유: 계정에서 내려오는 스킬과 이름이 겹쳐 어느 쪽이
로드됐는지 헷갈릴 수 있다. 리포에서 바로 쓰고 싶으면 옮기면 되지만, 그때는 계정 쪽
사본을 지워서 하나만 남기는 편이 낫다.

## 2026-08-11 — 앱과 스킬을 다시 맞췄다

회원이 물었다: "우리 블로그 스킬, 내가 채팅하면서 요구했던 게 오류 없이 정확하게 실행됐던 거지?"

**아니었다.** 8월 10~11일에 앱(`lib/ai/prompt.ts`·`lib/writing/checker.ts`)에 넣은 변경이 스킬 문서에는 하나도 반영되지 않았다. 스킬 사본은 2026-08-06 이후 손대지 않은 상태였고, **회원 지시와 정면으로 반대인 항목까지 남아 있었다** — 「협찬은 첫 화면에 표기, 맨 아래에만 넣지 마라」(회원 요청은 「제일 하단에」).

이번에 맞춘 것:

| 항목 | 앱 | 스킬 (이번에 반영) |
|---|---|---|
| 후기 아쉬운 점 | 삭제 → 좋았던 점 (혜택·가격과 이어서) | ✅ |
| 협찬 표기 위치 | 본문 맨 마지막 | ✅ |
| 제목에 홍보 한 조각 | 홍보·후기 필수 / 정보 제외 | ✅ |
| 후기 도입 로테이션 | 5가지, 2단계도 이어가기 | ✅ |
| 후기 도입에 이벤트 훅 | ㉮무엇이 있다 + ㉯제한이 있다 | ✅ |
| 정보글 출처를 문장 앞에 | 「○○에 따르면, …」 | ✅ (스킬엔 출처 규칙이 아예 없었다) |
| 정보글 분량 | 2,200~3,000자 | ✅ (스킬은 2,000자 — **앱 검수에서 걸리는 값이었다**) |
| 쓸 수 있는 표기 4개 | 소제목·굵게·이미지·구분선 | ✅ |
| 상호명 줄여 쓰지 않기 | 「두정점」 금지 | ✅ |
| 단위 기호·전부 한국어·평소 쓰는 말 | | ✅ |

**`gym-info-writer` 사본을 이 폴더에 새로 넣었다** — 여태 계정에만 있어서 컨테이너가 회수되면 사라지는 상태였다.

## 코드와의 관계

수치 기준(키워드 횟수·글자수·밀도)은 `lib/writing/checker.ts` 의 `SPECS` 에도 있고
스킬 문서에도 적혀 있다. **두 곳이 어긋나면 실제로 잘못된 글이 나온다** — 스킬을 보고
글을 쓰고, 코드로 검수하기 때문이다. `scripts/checks.mjs` 가 AI 지시문(`lib/ai/prompt.ts`)
과 코드의 일치는 검사하지만, **스킬 문서는 테스트로 잡히지 않는다.** 스킬을 고칠 때는
`SPECS` 와 같은 값인지 눈으로 확인할 것.
